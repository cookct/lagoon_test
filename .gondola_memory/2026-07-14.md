# Memory — 2026-07-14

## [gotcha] JSON comments break lore parsing silently
confidence: 0.95
JavaScript-style comments (//) in .lore.json files cause silent JSON parse failures. The anchor system returns empty array with no error message, making it appear as if the file doesn't exist.
---

## [architecture] Two lore file formats with different injection paths
confidence: 0.95
Entries-based lore files (with 'entries' array containing keywords) inject via keyword matching. Flat content files (just 'content' field) return empty from load_anchors() since it only reads data.get('entries', []) — they don't inject even if referenced in shared_lore.
---

## [gotcha] Lore scan excludes system messages
confidence: 0.9
The scan_and_inject() function explicitly filters out system messages when scanning for keywords. Keywords appearing in system_prompt won't trigger lore injection — only user/assistant message content is scanned.
---

## [architecture] lore_scan_depth default is 4 messages
confidence: 0.85
Keyword matching only scans the last 4 messages by default (configurable via lore_scan_depth). Older messages won't trigger lore injection even if they contain matching keywords.
---

## [gotcha] Session Archive doesn't inject via keyword system
confidence: 0.9
Session Archive files are flat content (no entries array), so load_anchors() returns empty. Even though referenced in character's shared_lore config, they don't get injected through the keyword trigger mechanism.
